# First custom puzzle room

This is the first Blood MAP in the project authored entirely from an empty
`LevelIR`. It copies no source geometry. The playable local build is generated by
`python -m bloodmap design-first-room`.

## Design

The room is a compact sequential puzzle with readable backtracking:

1. The player starts 896 units in front of a one-way wall switch in the main
   chamber.
2. Switch A sends command `On` over user channel 100. The east vertical door rises,
   revealing a differently shaded alcove.
3. Switch B is mounted on the far alcove wall. It sends `On` over channel 101.
4. The player returns to the main chamber; the wider north door is now open.
5. The north bay contains a sawed-off shotgun as the completion reward.

Four wall torches establish the main chamber's symmetry. Different wall/floor
materials distinguish the main chamber, machinery strips, alcove, and reward bay.
The connections are short rectangular thresholds rather than generated tapered
corridors.

## Geometry and behavior evidence

The map contains 5 sectors, 28 walls, and 7 sprites. Door A is 3072 units wide;
Door B is 4096 units wide. All four reciprocal portal pairs have 32768 units of
configured-open vertical clearance. With the construction gate set to a 2048-unit
minimum width and 8192-unit minimum height, every connection reports
`walkable_when_open: true`.

Both doors are native type-600 vertical-motion sectors. Each starts closed with its
ceiling at the floor and raises its ceiling from 8192 to -24576 in response to its
channel. Channels 100 and 101 each contain exactly one type-21 push-switch
transmitter and one door-sector receiver; both transmit command 1 (`On`).

Two builds are byte-identical at 1869 bytes. SHA-256:
`f0824e11a864ee4f712531aded4623800f9e228cbcd62222294a0c1e081d4988`.
The written MAP reparses with zero errors and zero warnings.

NBlood `r14378-fbc5e1186` initialized the map and remained healthy for the bounded
six-second load smoke. The public action oracle then confirmed that an idle control
view remains stable and pressing Use on Switch A creates a stable visible state
change while the engine remains healthy. A second isolated run with only the
temporary player start moved in front of Switch B passed the same interaction gate.
The Switch A and Switch B evidence is recorded in
`reports/nblood_first_puzzle_room_action.json` and
`reports/nblood_first_puzzle_room_switch_b_action.json`.
